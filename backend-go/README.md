# Backend Go — TermtemSL

REST API backend for the Thai Sign Language AI project, written in Go (Gin framework).  
The database and AI model service are **not yet connected** — this service handles HTTP routing
and file utilities and is ready to be extended.

---

## Project Structure

```
backend-go/
├── main.go                  # Entry point; Gin server on :8080 with Swagger metadata
├── go.mod / go.sum          # Module: project-backend (Go 1.26.4)
├── docs/                    # Auto-generated by swag — do not edit manually
│   ├── docs.go
│   ├── swagger.json
│   └── swagger.yaml
├── model/
│   ├── health_response.go   # HealthResponse struct
│   └── response.go          # Shared response structs (VideoUpload, Prediction)
├── routes/
│   ├── health_routes.go     # GET /health
│   ├── video_routes.go      # POST /api/videos/upload (stub — next step)
│   └── realtime_routes.go   # WebSocket stubs (future step)
├── services/
│   └── video_service.go     # Video business logic stubs (in progress)
├── utils/
│   └── file_utils.go        # File helpers; defines uploads/ and outputs/ dirs
├── Dockerfile               # Multi-stage Docker build
├── .dockerignore
└── .env.example             # Placeholder env vars for future use
```

Runtime directories (`uploads/`, `outputs/`) are created automatically by the application
and mounted as named Docker volumes when running via Compose.

## Running Locally (without Docker)

**Prerequisites:** Go 1.26.4+, and `swag` CLI (see below)

### 1. Install the `swag` CLI (one-time)

```powershell
go install github.com/swaggo/swag/cmd/swag@v1.8.12
```

> After installing, add `$env:GOPATH\bin` to your PATH if `swag` is not found:
> ```powershell
> $env:PATH += ";$(go env GOPATH)\bin"
> ```

### 2. Install / tidy dependencies

```powershell
cd backend-go
go mod tidy
```

### 3. Generate Swagger docs

Run this whenever you add or change Swagger annotations on any handler:

```powershell
swag init -g main.go
```

This regenerates `docs/docs.go`, `docs/swagger.json`, and `docs/swagger.yaml`.

### 4. Run the server

```powershell
go run .
```

The server starts at **http://localhost:8080**.

### Available URLs

| URL | Description |
|-----|-------------|
| http://localhost:8080/health | Returns `{"status":"ok"}` |
| http://localhost:8080/swagger/index.html | Interactive Swagger UI |

## Docker

> All Docker Compose commands are run from the **project root** (`termtemsl/`),
> not from inside `backend-go/`.

### Build the image

```powershell
docker compose build
```

### Start the container

```powershell
docker compose up -d
```

### Rebuild after code changes

```powershell
docker compose up -d --build
```

### View logs

```powershell
docker compose logs -f backend-go
```

### Stop the container

```powershell
docker compose down
```

### Stop and wipe named volumes (uploads + outputs)

```powershell
docker compose down -v
```

## Testing the API

**PowerShell:**

```powershell
# Health check
Invoke-RestMethod -Uri http://localhost:8080/health

# Swagger UI (opens in browser)
Start-Process "http://localhost:8080/swagger/index.html"
```

Expected health response:

```json
{"status":"ok"}
```

**curl (Git Bash / WSL):**

```bash
curl http://localhost:8080/health
```

## Backend Workflow

```
Flutter app
    │
    ▼ HTTP
Go Backend (:8080)
    │
    ├── GET  /health               → healthcheck
    ├── GET  /swagger/index.html   → Swagger UI
    └── POST /api/videos/upload    → (In progress)
              │
              ├── uploads/   → incoming video files (Docker named volume)
              └── outputs/   → processed results  (Docker named volume)
```

Future services (database, AI model) will be added as separate Docker Compose services.
