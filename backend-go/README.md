# Backend Go — TermtemSL

The main REST and business API for the TermtemSL Thai Sign Language project. It is built with Go, Gin, Swaggo, and PostgreSQL through `database/sql` with the pgx/v5 driver.

Current milestones:

- Milestone 1: Gin, Swagger, and `GET /health`
- Milestone 2: local video upload through `POST /api/videos/upload`
- Milestone 3: Supabase PostgreSQL connection and `GET /health/db`

The Python AI service is present elsewhere in the repository but is not connected to the Go API yet. Authentication, Supabase Storage, application tables, and realtime inference belong to later milestones.

The local `uploads/` and `outputs/` directories are runtime data. Docker Compose stores them in named volumes.

## API endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/health` | Go API liveness check |
| GET | `/health/db` | PostgreSQL connectivity check |
| POST | `/api/videos/upload` | Save a multipart video to local storage |
| GET | `/swagger/index.html` | Interactive Swagger UI |

The upload form field is named `video`. Supported filename extensions are `.mp4`, `.mov`, `.avi`, and `.mkv`.

## Environment configuration

Required:

```dotenv
DATABASE_URL=postgresql://...
```

Optional:

```dotenv
PORT=8080
```

Copy connection details from the Supabase Dashboard's **Connect** panel. Use TLS and do not commit the real database URL.

### Environment-file locations

For Docker Compose, keep one private environment file at the project root:

```text
termtemsl/
├── .env                    # ignored by Git
├── docker-compose.yml
└── backend-go/
    ├── Dockerfile
    └── .env.example        # placeholders only
```

`backend-go/.env` is not required. The Go application reads process environment variables and does not automatically load `.env` files.

Never expose `DATABASE_URL` to Flutter and never commit a real credential.

## Run locally without Docker

Prerequisites:

- Go 1.26.4 or the version declared in `go.mod`
- Access to the configured Supabase PostgreSQL project

From `backend-go`, install dependencies:

```powershell
go mod download
go mod tidy
```

Set configuration in the same PowerShell session:

```powershell
$env:PORT = "8080"
$env:DATABASE_URL = "your-real-supabase-connection-string"
go run .
```

Successful startup includes:

```text
Database connection established
Server running on http://localhost:8080
```

The server intentionally fails startup if `DATABASE_URL` is missing or PostgreSQL cannot be reached.

## Swagger

Install the Swaggo CLI once if necessary:

```powershell
go install github.com/swaggo/swag/cmd/swag@v1.8.12
$env:PATH += ";$(go env GOPATH)\bin"
```

Regenerate documentation after changing handler annotations:

```powershell
cd backend-go
swag init -g main.go
```

Open `http://localhost:8080/swagger/index.html` after starting the server.

## Run with Docker Compose

Run Compose commands from the project root, not from `backend-go`:

```powershell
cd C:\Users\USER\Downloads\senior_project\termtemsl
docker compose up -d --build
docker compose ps
docker compose logs backend-go
```

Compose reads `DATABASE_URL` from the private root `.env` and passes it to the Go container. The Go Dockerfile remains inside `backend-go` because the root Compose file uses `./backend-go` as its build context.

Stop the service with:

```powershell
docker compose down
```

Remove containers and the named upload/output volumes only when their stored files are no longer needed:

```powershell
docker compose down -v
```

## Test the API

Health:

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/health" |
  ConvertTo-Json
```

Expected response:

```json
{
  "status": "ok"
}
```

Database connectivity:

```powershell
Invoke-RestMethod -Uri "http://localhost:8080/health/db" |
  ConvertTo-Json
```

Expected response:

```json
{
  "status": "ok",
  "database": "connected"
}
```

Upload a video:

```powershell
curl.exe -X POST `
  -F "video=@C:\path\to\video.mp4" `
  "http://localhost:8080/api/videos/upload"
```

Expected response shape:

```json
{
  "filename": "generated-uuid.mp4",
  "message": "video uploaded successfully"
}
```

## Current backend flow

```text
Flutter or Swagger
        |
        v
Go/Gin API :8080
    |-- GET  /health
    |-- GET  /health/db ----------> Supabase PostgreSQL
    |-- POST /api/videos/upload --> local uploads directory
    `-- GET  /swagger/index.html
```

Milestone 3 establishes connectivity only. It does not create application tables, implement authentication, integrate Supabase Storage, call the Python AI service, or add caching.
